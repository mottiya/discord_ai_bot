# Архитектура

## Основной поток
1. `main.py` загружает настройки и промпты, валидирует наличие identity в конфиге
2. Создаёт два объекта `IdentityState` через фабрику `build_identity_state()`
3. Каждая личность работает как экземпляр `DiscordClient`, который слушает сообщения в указанном канале
4. При получении сообщения от оппонента оно обрабатывается через пайплайн LangGraph (`ai/graph.py`)
5. Пайплайн генерирует ответ и валидирует его перед отправкой в Discord

## Ключевые компоненты

**Настройки (`settings.py`)**: Конфигурация на базе Pydantic, загружаемая из `.env`. Все переменные окружения используют префикс `DBA__` с `__` в качестве разделителя вложенности (например, `DBA__DISCORD__CHANNEL_ID`).

**Пайплайн LangGraph (`ai/graph.py`)**: Граф из двух узлов:
- `gen_msg_node`: Генерирует ответ с помощью настроенной LLM
- `validate_msg_node`: Валидирует ответ (сейчас автоматически одобряет); отклонённые сообщения возвращаются на генерацию
- `create_identity_state()`: Фабрика для создания состояния личности

**Провайдер LLM (`ai/llm_getter.py`)**: Фабрика, выбирающая чат-модель LangChain по префиксу имени модели:
- `grok*` → ChatXAI
- `gpt*`, `o1*` → ChatOpenAI
- `mixtral*`, `llama*`, `gemma*`, `qwen*` → ChatGroq
- по умолчанию → ChatOpenAI

**Ресурсы (`resources_manager.py`)**: Асинхронный загрузчик YAML с использованием `aiofiles`. Загружает `ModelPromts` с конфигурациями личностей (`Identity`), индексированными по Discord user ID.

**Валидация (`main.py`)**: `validate_identities()` проверяет наличие всех identity из настроек в файле промптов при старте. При отсутствии выбрасывает `IdentityNotFoundError`.
